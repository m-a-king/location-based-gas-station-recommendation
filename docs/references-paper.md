### 3.1 후보 주유소 탐색 영역 설정

경로 기반 추천에서는 전체 경로 주변의 주유소
를 탐색 대상으로 설정해야 한다. 본 시스템에서는
경로 폴리라인을 감싸는 최소 경계 사각형
(Minimum Bounding Rectangle, MBR)을 구성하고,
이를 일정 거리만큼 확장하여 후보 탐색 영역을 정
의한다.

미터 단위의 버퍼 거리를 위도·경도 차이로 변
환하기 위해, 본 연구에서는 Snyder[7]의 위도·경
도 길이 관계를 참고하여 다음과 같은 단순 근사식
을 사용한다.

```
Δφ = d / 111320                          (1)
Δλ = d / (111320 × cos φ_mid)           (2)
```

여기서 d는 버퍼 거리(m), φ_mid는 폴리라인의
중간 위도(rad)이다. 식 (1)은 미터 단위의 거리를
위도 차이(도)로, 식 (2)는 경도 차이(도)로 변환한
다. 111,320은 지구 표면에서 1도에 해당하는 호
길이를 약 111.32km로 보는 구면 근사 상수이며,
경도 방향은 위도에 따라 cos φ 비율로 축소되는
관계를 반영한 것이다[7].

이렇게 구성된 MBR 내의 주유소를 데이터베이
스에서 1차 필터링한 후, 각 후보에 대해 경로까지
의 거리를 계산하여 설정된 버퍼 거리(2km) 이내
의 주유소만을 최종 후보로 선정한다.

### 3.2 거리 계산

1차 필터링을 통과한 후보 주유소와 경로 간의
거리 계산에는 Haversine 공식을 사용한다[6].
Haversine 공식은 지구를 반지름 R인 구로 가정하
고, 두 지점 간의 대원 거리(great-circle distance)
를 다음과 같이 계산한다.

```
h = sin²(Δφ/2) + cos φ₁ · cos φ₂ · sin²(Δλ/2)    (3)
d = 2R · arcsin(√h)                                 (4)
```

여기서 φ는 위도(rad), λ는 경도(rad), R은 지
구의 평균 반지름(6,371km)이다. Haversine 공식은
지구를 구로 근사하여 거리를 계산하므로 이론적인
오차는 존재하지만, 본 연구의 단거리 후보 필터링
목적에서는 실용적으로 사용 가능한 수준으로 본다.

경로(폴리라인)까지의 최소 거리는 폴리라인을
구성하는 각 선분에 대해 위경도 좌표 평면상에서
점-선분 최근접점을 구한 뒤, 해당 최근접점과의
Haversine 거리를 계산하여 최솟값을 취하는 방식
으로 구한다. 이때 최근접점 산출은 위경도를 평면
좌표로 간주하는 근사이므로 장거리에서는 오차가
커질 수 있으나, 2km 이내의 단거리 후보 필터링
목적에서는 실용적으로 충분한 정확도를 제공한다.

### 3.3 좌표 체계 변환

본 시스템은 OPINET API와 Kakao 지도 API를
함께 사용한다. OPINET API는 주유소 위치를 KATEC
좌표계(미터 단위)로 제공하는 반면, Kakao API 및
프론트엔드는 WGS84 좌표계(위도·경도 단위)를 사
용한다. 따라서 두 좌표 체계 간의 변환이 필요하
다.

KATEC 좌표계는 횡메르카토르(Transverse
Mercator) 투영에 기반한 투영 좌표계이다. 코드
구현에서는 KATEC 좌표계를 PROJ 문자열 파라미터
로 정의하여 사용하며, 횡메르카토르 투영의 일반
적인 수학적 배경은 Snyder[7]의 Chapter 8을 참
고하였다.

본 시스템에서는 이러한 투영 변환을 직접 구현
하는 대신, 오픈소스 좌표 변환 라이브러리인
Proj4J[8]를 활용하여 KATEC ↔ WGS84 간 변환을
수행한다. Proj4J는 PROJ 문자열 형식으로 좌표 참
조 체계(CRS)를 정의하고, 이를 바탕으로 좌표 변
환 연산을 제공하는 Java 라이브러리이다.

## 수정 이력 및 근거

이전 버전 대비 다음 사항을 수정하였다.

1. **111,320 상수**: "Snyder Table 4에서 직접 발췌"
   → "1도 ≈ 111.32km로 보는 구면 근사 상수"로 완화.
   "위도 1도당 자오선 호 길이"처럼 특정하면 과도한 단정이므로,
   위도/경도를 함께 다루는 단순 근사임을 반영.
   [v3] "위도 1도당 자오선 호 길이의 실용적 근사 상수" 표현도
   여전히 위도에 한정짓는 느낌이어서 재수정.

2. **cos(φ) 보정**: "Eq. 4-1에 근거" → 삭제.
   Eq. 4-1은 각왜곡(angular distortion) 식이며,
   경도 방향 호 길이와 cos φ의 관계는 별도의 일반적 관계이다.
   Snyder[7]를 "위도·경도 길이 관계"의 일반적 참고로만 인용.

3. **KATEC 파라미터**: "Snyder Table 10에서 정의"
   → Snyder는 TM 일반 공식의 근거로만 인용하고,
   KATEC 파라미터 자체는 코드 구현에서 사용한 CRS 정의로만 기술.
   본문에서 파라미터 나열(128°E, 38°N 등)도 제거하여
   직접 출처가 없는 값이 Snyder 근거로 읽히는 것을 방지.
   [v3] "중앙 자오선 128°E, 원점 위도 38°N, 축척 계수 0.9999"
   나열이 Snyder와 연결되어 보이는 문제를 구조적으로 분리.

4. **[8] PROJ → Proj4J 1.3.0**: 실제 의존성은
   `org.locationtech.proj4j:proj4j:1.3.0` (build.gradle.kts:31)이다.
   PROJ(C 라이브러리)와 Proj4J(Java 라이브러리)는 별개 프로젝트이므로,
   Proj4J를 직접 인용하도록 변경.
   [v3] 버전 번호 1.3.0을 참고문헌에 추가.
   [v4] 웹 저장소 인용의 연도 혼동을 피하기 위해 접근일 표기로 수정.

5. **"정밀 거리 계산" 표현 완화**: `GeoUtils.kt:33-41`의 점-선분 거리는
   위경도를 평면 좌표로 간주하는 근사 방식이다.
   "정밀"이라는 표현을 제거하고, 논문 본문에서 "단거리 후보 필터링
   목적에서 실용적으로 충분한 정확도"라고 명시.

6. **좌표 변환 정확도 검증 문구 삭제**: `CoordinateConverterTest.kt`의
   허용 오차(위도 0.03%, 경도 0.01%)는 sanity check 수준이며,
   논문에서 "정확도 검증"의 근거로 사용하기에는 불충분하므로
   본문에서 정확도 수치 언급을 제외.

7. **Haversine 오차 정량값 제거**: 별도 측지학 문헌 없이
   "최대 약 0.3%" 같은 수치를 제시하면 근거를 요구받을 수 있으므로,
   구면 근사에 따른 오차가 존재한다는 수준으로 보수적으로 완화.
