# gc — 논리적 단위로 분리된 git commit 수행

커밋 규칙을 준수하면서, 변경사항을 논리적 단위로 나눠 커밋한다.

## 커밋 메시지 형식

```
{타입}: {제목}

- 추가 설명 1
- 추가 설명 2
```

- 타입과 콜론 사이 공백 없음, 콜론 뒤 공백 1개
- 본문은 선택사항
- 언어: 한국어 권장, 기술 용어·고유명사는 영어 사용

## 허용 타입

- `feat:` — 새 기능
- `fix:` — 버그 수정
- `refactor:` — 동작 변경 없는 리팩토링
- `chore:` — 빌드, 설정 등 기타
- `docs:` — 문서 변경
- `test:` — 테스트 추가/수정
- `style:` — 코드 포맷, 세미콜론 등 로직 변경 없는 스타일

## 절차

1. `git status`와 `git diff`로 전체 변경 내역 파악
2. 변경 파일들을 **논리적 단위**로 그룹핑:
   - 같은 목적의 변경은 하나의 커밋
   - 서로 다른 관심사(도메인 타입 추가 / 서비스 리팩토링 / 테스트 / 설정 등)는 분리
   - 단, 억지로 나누지 말 것 — 자연스럽게 하나로 묶이면 한 커밋
3. 그룹별로 순서대로: `git add` → `git commit` 반복
4. `.md` 파일은 staged에서 제외 후 커밋
5. 전체 커밋 완료 후 `git log --oneline -5`로 결과 확인
